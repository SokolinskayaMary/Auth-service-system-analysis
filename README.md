# Authentication & Authorization Service

**System Analysis & Design | Portfolio Project**

Проектирование системы аутентификации и авторизации для веб- и мобильных приложений.

*End-to-end system analysis: requirements engineering, BPMN, UML, REST API design, RBAC, JWT authentication and PostgreSQL data modelling.*

---

## О проекте

Цель проекта — спроектировать централизованный сервис, который обеспечивает безопасную регистрацию пользователей, проверку их личности и разграничение доступа к защищённым ресурсам веб- и мобильных приложений.

Проект охватывает полный цикл системного анализа: от сбора требований и описания пользовательских сценариев до проектирования архитектуры, API-контрактов и реляционной базы данных.

**Формат:** учебный pet-project по системному анализу. В репозитории представлена проектная документация, а не программная реализация сервиса.

## Функциональные возможности

- Регистрация пользователей по номеру телефона с SMS-подтверждением.
- Аутентификация по номеру телефона и паролю.
- Дополнительная двухфакторная аутентификация через SMS.
- Выпуск и обновление access- и refresh-токенов.
- Управление пользовательскими сессиями и подключёнными устройствами (не более трёх).
- Разграничение доступа на основе ролей `USER` и `ADMIN` (RBAC).
- Управление ролями и блокировка пользователей администратором.
- Восстановление доступа к учётной записи.
- Вход через ранее привязанные Google и VK ID.

## Архитектура системы

Система включает следующие логические компоненты:

| Компонент | Ответственность |
|---|---|
| API Gateway | Приём и маршрутизация запросов, технические проверки |
| Registration Service | Управление процессом регистрации |
| Identity Provider (IdP) | Проверка учётных данных, управление пользователями, сессиями и токенами |
| Verification Service | Генерация и проверка SMS-кодов |
| Protected Backend | Проверка прав доступа и выполнение защищённых операций |
| PostgreSQL | Хранение пользователей, ролей, прав, устройств и сессий |

В ходе проектирования принято решение не выделять Token Service и Session Manager в самостоятельные сервисы: их функции выполняет IdP.

## Модель авторизации

Для управления доступом выбрана **RBAC (Role-Based Access Control)**.

Права пользователей определяются назначенными ролями и разрешениями на действия над ресурсами.

В системе предусмотрены две роли: `USER` и `ADMIN`.

При обращении к защищённому ресурсу система проверяет действительность токена, состояние сессии, статус учётной записи и наличие необходимых прав.

## Ключевые проектные решения

В ходе анализа были приняты следующие решения:

**Централизация аутентификации.** Веб- и мобильные приложения используют единый механизм проверки пользователей.

**Разделение ответственности компонентов.** API Gateway выполняет инфраструктурные функции, а IdP управляет идентификацией, сессиями и выпуском токенов.

**Серверное управление сессиями.** Действительность JWT не заменяет проверку состояния пользовательской сессии.

**Ролевая модель доступа.** Для назначения разрешений используется RBAC с отдельными сущностями пользователей, ролей и прав.

**Реляционное хранение данных.** PostgreSQL обеспечивает ограничения целостности и управление связями между сущностями.
