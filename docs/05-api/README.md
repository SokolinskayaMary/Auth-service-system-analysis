# REST API — система аутентификации и авторизации

## Назначение

В разделе представлена спецификация REST API системы аутентификации и авторизации для веб- и мобильных приложений.

Контракт разработан в формате **OpenAPI 3.1** и описывает доступные операции, параметры запросов, схемы данных, HTTP-статусы и возможные ошибки.

## Спецификация

[Открыть OpenAPI YAML](openapi.yaml)

Спецификацию можно открыть в Swagger Editor для просмотра и проверки.

## Группы API

| Группа | Назначение |
|---|---|
| Registration | Регистрация по номеру телефона и подтверждение SMS-кода |
| Authentication | Вход по телефону и паролю, подтверждение второго фактора |
| Sessions | Управление пользовательскими сессиями, выход и обновление токенов |
| Profile | Получение данных текущего пользователя |
| Two-Factor Authentication | Управление настройкой SMS-2FA |
| PasswordRecovery | Восстановление пароля по секретному ответу или SMS |
| OAuth | Вход через ранее привязанные Google и VK ID |
| Administration | Изменение ролей и статусов пользователей |

## Основные проектные решения

### Регистрация

Регистрация выполняется только по номеру телефона.

Для связи этапов SMS-подтверждения используется `challenge_id`. После успешного завершения регистрации пользователю назначаются роль `USER` и статус `ACTIVE`.

### Аутентификация

Для входа используется номер телефона и пароль. Если включена двухфакторная аутентификация, дополнительно требуется подтверждение SMS-кода.

После успешной проверки IdP создаёт серверную сессию и выпускает access- и refresh-токены.

### Авторизация

Действительность JWT сама по себе не гарантирует разрешение на выполнение операции.

Сервер дополнительно проверяет состояние пользовательской сессии, статус учётной записи и разрешения роли.

### Восстановление пароля

Предусмотрены два альтернативных способа подтверждения личности:

- Ответ на секретный вопрос.
- SMS-код, если пользователь не помнит ответ.

Для восстановления используются два endpoint: `/auth/password/reset/start` и `/auth/password/reset/confirm`.
