# Интервью по сбору требований
**Цель интервью**: определить основные требования к регистрации, аутентификации, авторизации, управлению пользовательскими учётными записями и восстановлению доступа.

Документ фиксирует ответы, полученные на этапе сбора требований. Последующие уточнения и принятые решения отражены в техническом задании.

## Вопрос 1. По каким данным пользователь будет входить в систему?

Вопрос: Будет ли пользователь входить по номеру телефона, электронной почте или другим данным? Как должен происходить первый вход?

Ответ: Вход осуществляется по номеру телефона.

При регистрации пользователь вводит номер телефона, на который отправляется SMS-код подтверждения. После успешной проверки кода пользователь устанавливает пароль.

Для мобильного приложения необходимо предусмотреть возможность быстрого входа с помощью Face ID или короткого PIN-кода.

## Вопрос 2. Необходимо ли реализовать регистрацию пользователей?

Вопрос: Требуется ли отдельный механизм регистрации или учётные записи будут создаваться в другой системе? Какие данные необходимо получать при регистрации?

Ответ: Регистрация необходима.Пользователь должен предоставить следующие данные:

Номер телефона.

ФИО.

Дату рождения.

Ответ на секретный вопрос, предложенный системой.

Пароль для последующего входа.

## Вопрос 3. Какие требования предъявляются к многофакторной аутентификации и количеству устройств?

Вопрос: Сколько устройств может использовать один пользователь? Нужна ли двухфакторная аутентификация и какие способы подтверждения должны поддерживаться?

Ответ: Система должна поддерживать одновременную работу пользователя не более чем на трёх устройствах. В веб-приложении необходимо предоставить возможность просмотра и управления подключёнными устройствами.

Двухфакторная аутентификация предпочтительна.

Предусмотрены следующие способы входа:

Веб-приложение: пароль и дополнительный SMS-код.

Мобильное приложение: Face ID или быстрый PIN-код с дополнительным SMS-подтверждением.

## Вопрос 4. Какие статусы могут быть у пользователя?

Вопрос: Какие состояния учётной записи необходимо предусмотреть? Пользователям с какими статусами разрешён доступ к системе?

Ответ: Предусмотрены три статуса:

ACTIVE — активный пользователь, которому разрешён доступ к ресурсам системы.

BLOCKED — пользователь, заблокированный администратором. Доступ к системе запрещён.

INACTIVE — пользователь, который не входил в систему более двух месяцев.

Заблокировать и разблокировать пользователя может только администратор.

## Вопрос 5. Какая ролевая модель необходима?

Вопрос: Какие роли будут существовать в системе и кто сможет управлять ими?

Ответ: Предусмотрены две роли:

USER — обычный пользователь.

ADMIN — администратор.

Администратор может назначить пользователю роль администратора.

## Вопрос 6. Как долго должны действовать токены и пользовательские сессии?

Вопрос: Как долго пользователь может оставаться в системе? Выдаётся ли токен отдельно для каждого устройства?

Ответ: Пользователь должен иметь возможность работать с нескольких устройств, при этом каждая авторизация связана с конкретным устройством.

Токен выдается на одно устройство и живет пока пользователя не выйдет из системы или не активничает более трёх минут.

## Вопрос 7. Какие данные используются при восстановлении доступа?

Вопрос: Что должен сделать пользователь, если он забыл пароль?

Ответ: При регистрации пользователь задаёт ответ на секретный вопрос, предложенный системой.

Если пользователь забыл пароль, он может ответить на секретный вопрос и установить новый пароль, введя его дважды.

Если пользователь не помнит ответ на секретный вопрос, необходимо предусмотреть альтернативное восстановление через подтверждение номера телефона.

## Вопрос 8. Как должен происходить процесс восстановления пароля через телефон?

Вопрос: Что происходит, если пользователь не может вспомнить ответ на секретный вопрос?

Ответ: Пользователь вводит номер телефона, использованный при регистрации.

Система проверяет номер и отправляет SMS-код.

После успешного подтверждения номера пользователь переходит к форме изменения пароля.

Пользователь вводит новый пароль дважды и сохраняет его.

## Вопрос 9. Нужна ли возможность входа через сторонние сервисы?

Вопрос: Должна ли система поддерживать вход через внешние сервисы авторизации? Если да, какие именно?

Ответ: Да, необходимо предусмотреть вход через:

Google.

VK ID.
