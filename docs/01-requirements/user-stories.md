# User Stories — система аутентификации и авторизации

## Назначение документа

В документе представлены пользовательские истории, выявленные на этапе анализа требований к системе аутентификации и авторизации веб- и мобильных приложений.

User Stories описывают потребности пользователей и администраторов без детализации технической реализации. Соответствующие варианты использования описаны в документе `use-cases.md`.

## US-01. Регистрация пользователя

**Роль:** Новый пользователь.

**User Story:** Как новый пользователь, я хочу зарегистрироваться в системе по номеру телефона, чтобы создать учётную запись и получить доступ к возможностям приложения.

**Ценность:** Пользователь может самостоятельно создать аккаунт и начать работу с приложением.

**Связанный Use Case:** UC-01 — Регистрация нового пользователя.

## US-02. Вход в систему

**Роль:** Зарегистрированный пользователь.

**User Story:** Как зарегистрированный пользователь, я хочу входить в систему по номеру телефона и паролю, чтобы получать доступ к своей учётной записи и разрешённым функциям приложения.

**Ценность:** Пользователь может безопасно получать доступ к своим данным и продолжать работу с приложением.

**Связанный Use Case:** UC-02 — Вход в систему.

## US-03. Восстановление пароля

**Роль:** Пользователь, забывший пароль.

**User Story:** Как зарегистрированный пользователь, я хочу иметь возможность восстановить забытый пароль, чтобы вернуть доступ к своей учётной записи.

**Ценность:** Пользователь может восстановить доступ без создания новой учётной записи.

**Связанный Use Case:** UC-03 — Восстановление пароля.

## US-04. Управление учётными записями

**Роль:** Администратор.

**User Story:** Как администратор системы, я хочу управлять ролями и статусами пользователей, чтобы контролировать их доступ к приложению и обеспечивать безопасность системы.

**Ценность:** Администратор может управлять полномочиями пользователей, блокировать учётные записи и восстанавливать доступ после снятия блокировки.

**Связанный Use Case:** UC-04 — Управление учётными записями.

## US-05. Вход через сторонний сервис

**Роль:** Зарегистрированный пользователь.

**User Story:** Как зарегистрированный пользователь, я хочу входить в систему через ранее привязанный аккаунт Google или VK ID, чтобы использовать удобный альтернативный способ аутентификации.

**Ценность:** Пользователь может входить в существующую учётную запись без повторного ввода основного пароля.

**Связанный Use Case:** UC-05 — Вход через сторонний сервис.
